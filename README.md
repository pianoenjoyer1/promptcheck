# PromptCheck

Небольшой инструмент для воспроизводимой проверки сохранённых ответов языковой модели. Сравнивает ответы с набором правил и выдаёт Markdown или JSON-отчёт с причиной каждого провала.

**Python 3.9+ · Без зависимостей и API-ключей · Подходит для CI**

## Задача

После изменения промпта ответ может потерять обязательный JSON-ключ, стать слишком длинным или содержать запрещённую фразу. PromptCheck позволяет сохранить такие требования как тестовые случаи и повторять проверку.

Инструмент не вызывает модель: ответы нужно получить отдельно и сохранить в JSONL. Демонстрационные ответы составлены вручную, это не результаты реального сравнения моделей.

## Быстрый запуск

В корневой папке проекта:

```bash
python3 promptcheck.py examples/cases.jsonl examples/responses-good.jsonl
python3 promptcheck.py examples/cases.jsonl examples/responses-bad.jsonl
python3 promptcheck.py examples/cases.jsonl examples/responses-good.jsonl --format json --output report.json
```

Первый пример: **4/4 PASS**. Второй: **1/4 PASS**, код завершения **1** — ожидаемый результат для специально плохих ответов. На Windows можно использовать `python`.

## Формат данных

Один JSON-объект на строку. В `cases.jsonl`:

```json
{"id":"plan","prompt":"Верни план в JSON","checks":{"json_object":true,"required_keys":["title","steps"]}}
```

В файле ответов:

```json
{"id":"plan","response":"{\"title\":\"Demo\",\"steps\":[\"Test\"]}"}
```

Поле `prompt` служит описанием для человека. Сопоставление выполняется по уникальному строковому `id`; отсутствие ответа проваливает случай. Лишний или повторяющийся `id` считается ошибкой входных данных.

| Правило | Значение | Проверка |
|---|---|---|
| `contains` | Непустой массив строк | Каждая подстрока присутствует, регистр игнорируется |
| `not_contains` | Непустой массив строк | Ни одной подстроки нет, регистр игнорируется |
| `max_words` | Целое число ≥ 0 | Число групп непробельных символов не превышает лимит |
| `json_object` | `true` | Ответ целиком является JSON-объектом |
| `required_keys` | Непустой массив строк | JSON-объект содержит все ключи верхнего уровня |

`required_keys` также включает проверку JSON-объекта. Типы значений не проверяются. Markdown-ограждения вокруг JSON не удаляются; ответ должен соответствовать формату целиком. Неизвестные правила отклоняются, чтобы опечатка не дала ложный PASS.

## Результат и автоматизация

Случай проходит, только если прошли все его проверки. `pass_rate` — доля прошедших случаев, а не отдельных правил. Вывод JSON содержит `total`, `passed`, `failed`, `pass_rate` и подробности `cases`.

- `0`: все случаи прошли.
- `1`: хотя бы один случай провалился.
- `2`: неправильные аргументы или входные данные.

`--output` сохраняет отчёт. Входные файлы нельзя перезаписать отчётом. Пример итогового документа: [examples/report.md](examples/report.md).

## Проверка

```bash
python3 -m unittest discover -s tests -v
```

Тесты покрывают хорошие и плохие ответы, отсутствующие и повторяющиеся ID, неверные правила, JSON-структуру, регистр, длину, ошибки JSONL и код завершения CLI.

## Ограничения и развитие

Подстрока может присутствовать в неправильном по смыслу ответе. Эти проверки не измеряют правдивость, безопасность, полезность или общее качество модели. Следующие шаги: проверка типов JSON-полей, сравнение двух отчётов и отдельная человеческая оценка смысла ответов.

Учебный прототип, подготовленный с помощью AI-инструментов. Код и тестовые примеры доступны для изучения и доработки.
